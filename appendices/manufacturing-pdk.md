## Part 1 — What is real: digital physical design (ASAP7 / OpenROAD)

### The PDK itself — predictive/academic, not a real foundry process

**ASAP7 is a predictive 7nm-class PDK for academic/pre-competitive
research.** It does not correspond to any real, commercially available
foundry process — there is no foundry that will accept an ASAP7 design
for fabrication. Every physical-design number in this program (area,
timing, power) is real *tool output* against this predictive PDK, not
a prediction of what a real commercial 7nm process would produce.
Treat every number below as "what this digital logic looks like when
placed and routed against a predictive 7nm model," never as a
manufacturing quote.

### Memory macros — FakeRAM2.0, a blackbox stand-in

Every SRAM macro in the ASAP7 runs above is generated by
[FakeRAM2.0](https://github.com/maliberty/FakeRAM2.0.git), a standard
OpenROAD-ecosystem technique for a memory that has not been compiled by
a real SRAM compiler: it produces a real, geometrically valid LEF/GDS
blackbox with **placeholder, generic leakage/power characterization**.
The B-operand macro's real dimensions are
**132.81 µm × 331.8 µm** after fixing a genuine early defect
(`column_mux_factor=1` produced a physically absurd 8.36 × 5308.8 µm,
~635:1 aspect-ratio shape, rejected by the placer's own `-min_ar 0.33`
bound). **FakeRAM's reported power (87.45 W total on the A-operand run,
86.1 W of it the macro group) is not a real power number — do not use
it for thermal design.**

### Digital test evidence that actually exists

The **only** test evidence in this program, anywhere, is RTL
simulation — no board, no silicon, no bench measurement:

| Testbench | File | What it exercises |
|---|---|---|
| `tb_cs_fifo_path` | `gcb-rtl/sim/tb_cs_fifo_path.sv` | Carry-save lane FIFOs, M_AXIS_CS ingress |
| `tb_dma_integration` | `gcb-rtl/sim/tb_dma_integration.sv` | Streaming Tensor DMA descriptor ring end-to-end |
| `tb_ss_calib` | `gcb-rtl/sim/tb_ss_calib.sv` | Single-slope calibration polynomial, 10,000/10,000 bit-exact vs. Python golden model |
| `tb_ss_tdc` | `gcb-rtl/sim/tb_ss_tdc.sv` | Single-slope TDC Gray-counter/capture logic |
| `tb_ss_energy` | `gcb-rtl/sim/tb_ss_energy.sv` | Energy/toggle-count accounting for the readout chain |

All run via Icarus Verilog (`sim/run_dma_tb.sh`, `run_pilot_tb.sh`,
`run_ss_tb.sh`) — **these are digital-logic regressions, not board- or
silicon-level test vectors.** No automated test equipment (ATE)
program, no board-level functional test fixture, and no wafer-probe
test plan exists anywhere in this program's real artifacts.

## Part 2 — What is not yet real: tapeout, package, PCB, board, physical test

**Read this section as a gap list, not a specification.** Nothing
below has a real design artifact behind it in this program today.

| Question | Status |
|---|---|
| Wafer tapeout (any process, "Tiny Tapeout" or otherwise) | **Not started.** No tapeout submission, no shuttle run, no process-design-kit qualification for a real foundry. ASAP7's predictive nature (Part 1) means the existing physical-design work cannot be submitted as-is to any real fab. |
| Die-to-package connectivity (bond wire, flip-chip, RDL) | **Not started.** No package model, no bond-wire inductance/parasitic model, no bump map. |
| Package-to-PCB footprint / pinout | **Not started.** No package outline, no BGA/QFN pinout, no pin-assignment document. |
| PCB layer stackup, DRC rules | **Not started.** No PCB design exists for any GCB-specific board — the Alveo U55C used for Track A's real FPGA results is a commercial off-the-shelf card, not a GCB-designed board. |
| Board assembly process (pick-and-place, reflow, AOI) | **Not started** — no board to assemble. |
| Silicon test program (wafer probe, ATE test vectors) | **Not started** — no silicon exists to test. |
| Board-level functional test / system test | **Partially analogous, not equivalent:** the Icarus/cocotb regressions in Part 1 are the closest thing to a "test plan" this program has, but they test RTL in simulation, not an assembled board. |

**If/when this program pursues a real ASIC path**, the natural order
would be: commercial-PDK re-implementation (Part 1's ASAP7 results
would need to be redone against a real, licensed PDK) → tapeout →
package selection → PCB design around that package → board bring-up →
a board-level test program built from (and extending) the existing
RTL regressions. None of those steps has begun. This appendix exists
so that gap is recorded explicitly rather than discovered by a reader
assuming otherwise from a lens document that only shows the parts that
*are* built.

## Epistemic status, stated plainly

Part 1 is `PROVEN` — real tool output, independently verified this
session. Part 2 is not a forecast or a roadmap commitment; it is a
direct, checked list of what does not exist, kept here so neither
silicon/physical-design readers nor board/systems readers have to
independently discover the same gap from two different lenses.
